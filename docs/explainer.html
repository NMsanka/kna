KNA

A search engine that has actually read your code.

Ask it anything about your company's software. It answers in plain English, then shows you the exact file and line it got that from.

The problem it solves

A company ends up with forty or fifty separate code repositories. The person who wrote the billing service left last year. The written documentation was accurate in 2023.

So when someone needs to know how a thing works, there are two options: read code for an afternoon, or interrupt whoever already knows. Both are expensive, and the second one has a queue.

How it works

Why not just ask ChatGPT?

A general chatbot has never seen your company's code. These are the four differences that matter.

It only knows your code

Nothing general, nothing borrowed from the internet. If the answer isn't somewhere in your repositories, it doesn't have one.

Every answer has receipts

Each claim arrives with the file and line number behind it. You never have to take its word for anything — you can go and look.

It says when it doesn't know

If what it found is thin, it refuses rather than guessing. A confident wrong answer about your payment code is worse than no answer at all.

It respects who you are

You only ever see code you already have permission to read. Two people asking the same question can correctly get different answers.

Where you use it

Mostly inside the code editor, right next to whatever you're working on — it works out which project you mean from the folder you have open, so there's nothing to configure. There's a terminal command too, for when you're not in an editor.

Where it's at. A working system rather than a demo — today it indexes two repositories and roughly 2,500 functions and classes on a single laptop, and answers questions about them with citations.
